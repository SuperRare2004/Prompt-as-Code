\chapter{AI会犯哪些错：系统性认知}

前面的章节介绍了如何向 AI 描述问题、数据和建模任务。完成这些步骤后，AI 往往能够迅速生成代码、训练模型、绘制图表，并写出一段结构完整的结果解释。但项目到这里并没有结束。接下来还有一个无法外包给 AI 的问题：\textbf{这个结果到底对不对？}

传统程序中的错误经常以报错信息出现，使用者很容易意识到需要停止。AI 辅助机器学习中的许多错误却不会触发报错。代码能够运行，模型分数看起来不错，解释文字也十分流畅，但项目可能使用了错误字段、错误划分方式或错误评价指标。AI 可以让人更快得到一个答案，却不能保证这个答案值得相信。

本章首先建立对 AI 错误的系统认识。重点不是穷举所有可能问题，而是学习识别机器学习项目中最常见的五类错误：技术性错误、统计性错误、数据性错误、领域性错误和幻觉性错误。不同错误需要不同的发现方法，也需要不同程度的专业知识。

% ----------------------------------------------------------------
\section{AI错误的五种常见类型}
% ----------------------------------------------------------------

\subsection{技术性错误：代码没有正确完成指定计算}

技术性错误包括语法错误、函数调用错误、变量使用错误和计算逻辑错误。它们是最接近传统编程错误的一类，也是通常最容易验证的一类。

语法错误并不可怕，因为程序会停止并给出报错信息。真正需要警惕的是代码能够运行，却没有执行预期计算。例如：

\begin{itemize}
  \item 构造滞后特征前没有按路段分组，导致不同路段的数据相互污染；
  \item 合并两个表格时使用了不唯一的键，使部分记录被重复计算；
  \item 计算平均速度时把表示设备离线的零值当作正常速度；
  \item 修改了数据类型后，时间字段按照字符串顺序而不是时间顺序排序；
  \item 评价指标的真实值和预测值顺序写反，代码仍然正常运行。
\end{itemize}

技术性错误的共同特点是：任务定义和方法可能没有问题，但 AI 生成的实现没有正确执行它们。发现这类错误，不能只看代码是否报错，还应检查中间结果，并使用能够手工计算的小样本验证关键函数。

\paragraph{案例：跨路段的滚动平均}

假设需要为每条路段计算过去三个时间步的平均速度。AI 生成代码后直接对整张表使用滚动平均函数，却没有先按路段分组。第一条路段末尾的速度会进入第二条路段开头的特征中。代码不会报错，生成的新列也没有缺失格式问题，但特征已经失去真实含义。

一个简单的验证方法，是构造两条速度差异明显的路段，每条只有几条记录。如果第二条路段开头的滚动平均受到第一条路段影响，错误会立即暴露。

\subsection{统计性错误：方法运行正常，但评价或推断不成立}

统计性错误不是代码写错，而是方法选择、数据划分或指标解释不正确。这类错误经常产生非常漂亮的结果，因此比普通报错更危险。

\paragraph{数据泄露}

数据泄露是最常见的统计性错误之一。它指模型训练或评价时使用了真实预测中无法获得的信息。例如，使用事故发生后的处理时长预测事故是否发生；在划分训练集和测试集之前对全部数据进行标准化；随机划分具有明显时间关系的数据。

泄露发生后，模型相当于提前看到了部分答案，测试分数会异常优秀。代码通常完全正常，只有回到预测时点，逐个检查特征在预测时是否可用，才能发现问题\cite{kaufman2012leakage}。

\paragraph{指标选择不当}

不同指标回答不同问题。事故样本只占全部记录的 1\% 时，把所有样本预测为“无事故”便可以获得 99\% Accuracy，但这个模型没有识别出任何真正需要关注的事故。

如果漏报比误报更危险，就需要重点关注 Recall；如果需要在有限资源下提高预警准确性，则还要关注 Precision；如果输出概率将用于风险排序，还需要检查概率和排序是否可靠。指标必须由真实任务决定，而不能由 AI 使用默认选项。

\paragraph{把一次高分当作稳定能力}

AI 可以快速尝试大量模型和参数组合。如果反复查看同一验证集，并只保留表现最好的结果，最终高分可能部分来自偶然性。可靠比较应保留简单基准、记录尝试过的方案，并使用独立测试集确认最终结果。

\subsection{数据性错误：正确代码处理了错误含义}

数据性错误发生在 AI 对数据的理解与真实情况不一致时。此时，代码可能完全正确，统计方法也可能合理，但输入数据没有表示使用者以为的对象。

\paragraph{字段含义和单位错误}

同一个字段名在不同数据集中可能具有不同含义。例如，\texttt{flow} 可能表示车辆数、辆/5分钟或换算后的辆/小时；速度可能是瞬时速度、时间平均速度或空间平均速度。单位或定义错误会直接改变后续分析，却很难从代码中发现。

\paragraph{异常值含义错误}

AI 常会使用通用统计规则处理异常值，但领域中的异常值可能是真实且重要的信号。事故造成的速度骤降、大型活动产生的客流峰值、极端天气下的需求变化，都不应仅因为“偏离平均水平”而被删除。

\paragraph{标签并不天然正确}

事故严重程度、拥堵状态和乘客满意度等标签都依赖具体定义与记录方式。已报告事故不等于全部实际事故；投诉较多可能表示服务问题严重，也可能表示投诉渠道更便利。模型学习的是数据中的标签规律，而不是自动学习现实中的真实概念。

发现数据性错误，需要理解数据如何采集、每行代表什么、字段如何生成，以及哪些对象没有进入数据。这也是为什么向 AI 提供数据字典和领域背景如此重要。

\subsection{领域性错误：统计上合理，现实中却不合理}

领域性错误是指结果在代码和统计上看似成立，却违背专业常识、业务规则或现实约束。这类错误通常最难由 AI 自己发现，因为相关知识并不完整地存在于 Prompt 和数据中。

例如：

\begin{itemize}
  \item 模型建议使用实际部署时无法实时获取的字段；
  \item 公交调度方案要求的班次调整违反运营规则；
  \item 预测结果长期出现负流量或明显超过道路容量；
  \item 模型在普通工作日表现很好，却被直接用于节假日和极端天气；
  \item AI 根据相关关系提出政策建议，却没有考虑其他可能原因。
\end{itemize}

领域性错误说明，一个统计分数不能独立证明模型有用。结果还需要通过数量级、方向、可执行性和适用场景的检查。

\paragraph{案例：负流量预测}

某回归模型在测试集上的平均误差不高，但在低流量时段会输出负数。若只看总体指标，这个问题可能不明显；从交通工程常识看，负流量显然不可能。领域知识在这里提供了一个比平均误差更直接的正确性标准。

\subsection{幻觉性错误：AI生成了不存在或不准确的信息}

幻觉性错误包括编造文献、软件参数、法规条款、数据来源和计算结果。它也可能表现得更加隐蔽：引用真实存在，但原文并不支持 AI 写出的结论。

大语言模型根据上下文生成最符合语言模式的内容，而不是每次都先查找并核实事实。流畅表达本身不能证明事实成立\cite{bender2021stochastic}。因此，以下内容必须回到原始来源核验：

\begin{itemize}
  \item 文献题目、作者、结论和适用范围；
  \item 软件函数、参数名称和默认行为；
  \item 法规、标准和技术规范；
  \item 数据集字段定义与来源；
  \item 报告中的具体数字和比例。
\end{itemize}

尤其不能让 AI 在没有运行代码的情况下“估计”模型分数，也不能直接把 AI 生成的文献引用放入正式报告。

\section{为什么AI会“自信地”犯错}
% ----------------------------------------------------------------

\subsection{AI优化的是合理表达，不是事实保证}

大语言模型非常擅长生成连贯、完整且符合语境的回答，但“听起来合理”和“实际正确”不是同一件事。面对信息不足的问题，AI 通常仍会继续回答，而不是自动停止。

这意味着，回答语气越确定，并不代表事实越可靠；代码越完整，也不代表方法越正确；解释越详细，也不代表证据越充分。评价 AI 输出时，应把表达质量与内容正确性分开。

\subsection{专业长尾知识更容易出错}

AI 在常见编程模式、通用机器学习知识和公开资料上通常表现较好，但在具体城市、特定数据平台、内部业务规则和专业长尾知识上更容易犯错。

例如，AI 可能知道一般的交通流分析方法，却不知道某个检测器字段中的零值代表设备离线；知道常见事故分类，却不知道当前地区采用的正式分类标准；知道某个软件库的旧接口，却不知道当前版本已经修改参数。

任务越依赖本地信息和专业细节，越需要在 Prompt 中补充上下文，并加强核验。

\subsection{AI不会因为不确定而自动沉默}

使用者经常希望 AI 在不知道时直接说“不知道”，但 AI 并不总能准确判断自己的知识边界。它可能把模糊记忆、常见模式和上下文暗示组合成一个确定回答。

可以通过 Prompt 降低这种风险，例如：

\begin{quote}
如果缺少足够信息，请明确指出缺失内容，不要自行补充事实。对于具体数字、文献和软件参数，请说明核验来源；无法核实时请标记为待确认。
\end{quote}

但 Prompt 只能提醒 AI，不能替代外部核验。

\section{为什么领域知识决定你能发现多少错误}
% ----------------------------------------------------------------

AI 能够降低代码实现和资料整理的门槛，却不能取消领域知识的重要性。恰恰相反，当代码生成变得容易后，人的主要工作更集中在判断问题是否合理、数据是否被正确理解，以及结果是否符合现实。

\subsection{没有领域知识，很难知道应该检查什么}

不熟悉交通数据的人看到速度为零，可能认为它一定是异常值；熟悉数据采集机制的人会进一步询问：它发生在信号交叉口、严重拥堵期间，还是设备离线状态？同一个数值可能需要完全不同的处理。

领域知识不仅帮助回答问题，还帮助提出正确的检查问题。它告诉使用者哪些数量级不合理、哪些字段不可能实时获得、哪些场景必须单独评价，以及哪些结论不能从现有数据推出。

\subsection{AI不能替你定义“合理”}

模型是否合理，最终取决于它服务的现实任务。事故漏报与误报的代价如何权衡，节假日预测是否必须准确，某种调度方案是否能够执行，这些标准不写在算法里，也不能由 AI 自动决定。

因此，AI 的“天花板”往往是使用者能够提供和运用的领域知识。领域基础不足时，AI 可以帮助学习概念和发现问题，但重要结论仍需要教材、原始资料和专业人员核验。

\subsection{与AI协作可以反过来暴露知识缺口}

领域知识重要，并不意味着使用者必须在开始前知道所有答案。AI 可以帮助列出需要确认的问题、比较不同解释、生成检查清单，并指出当前分析依赖哪些假设。

例如，可以反向询问：

\begin{quote}
如果要判断这份交通预测结果是否合理，一名交通工程师需要提供哪些领域信息？请按数据含义、数量级、特殊场景和实际部署约束分类列出。
\end{quote}

这类提问不会替代领域判断，但可以帮助使用者发现自己还需要补充什么知识。

\section{建立系统性的错误检查习惯}
% ----------------------------------------------------------------

面对 AI 生成的结果，不需要怀疑每一个字符，但应优先检查会实质改变项目结论的环节。

\subsection{先检查上游，再检查最终结果}

一个实用的检查顺序是：

\begin{enumerate}
  \item AI 是否正确理解了任务目标和预测时点；
  \item 字段、单位、标签和异常值是否被正确理解；
  \item 数据处理后的行数、范围和样例是否符合预期；
  \item 特征、预处理和数据划分是否存在泄露；
  \item 模型是否优于简单基准，指标是否符合任务目标；
  \item 数字、图形和解释是否符合领域常识；
  \item 引用和具体事实是否经过原始来源核验。
\end{enumerate}

上游错误会影响全部下游结果。若标签定义错误，继续检查模型参数没有意义；若测试集发生泄露，漂亮分数也不能被采用。

\subsection{高分和“符合预期”的结果更值得检查}

异常糟糕的结果容易引起怀疑，异常优秀的结果却容易被接受。但模型表现远高于基准时，可能存在数据泄露、重复记录或评价错误；结果完全符合使用者预期时，也可能存在确认偏误。

看到高分时，可以先问：

\begin{itemize}
  \item 是否使用了预测时无法获得的信息；
  \item 训练集和测试集是否存在重复或时间交叉；
  \item 是否选择了过于容易的指标；
  \item 是否只报告了表现最好的一次实验；
  \item 简单基准的表现是多少。
\end{itemize}

\subsection{让错误修复进入下一轮Prompt}

发现错误后，不应只修改当前输出，还应把修复转化为新的 Prompt 约束和检查步骤。例如：

\begin{itemize}
  \item 字段含义被误解后，将数据字典加入后续 Prompt；
  \item 发生时间泄露后，明确所有特征只能使用预测时刻之前的信息；
  \item 异常值被误删后，要求 AI 先展示异常记录并等待确认；
  \item 引用出现错误后，要求关键事实标记来源和待核验状态；
  \item 一次性流程出错后，将任务拆成逐步确认的 Prompt 链。
\end{itemize}

这正是 Prompt as Code 的含义之一：错误检查得到的经验，应当像修改代码一样进入下一版 Prompt，使同类错误更难再次发生。

\section{实战练习：找出AI结果中的错误}
% ----------------------------------------------------------------

\subsection*{练习一：错误分类}

判断以下问题分别属于技术性、统计性、数据性、领域性还是幻觉性错误，并说明理由：

\begin{enumerate}
  \item AI 使用不存在的软件参数，代码运行时报错；
  \item 时序预测模型随机划分训练集和测试集，得到异常高分；
  \item AI 将检测器离线产生的零速度解释为严重拥堵；
  \item 模型预测某路段未来流量为负数；
  \item 报告引用了一篇真实论文，但论文并未支持报告中的因果结论。
\end{enumerate}

\subsection*{练习二：检查高分模型}

一个事故预测模型报告 Accuracy 为 98.7\%。请列出至少六项优先检查内容，覆盖任务、数据、实现、评价和领域合理性。

\subsection*{练习三：找出代码逻辑风险}

AI 生成了一段“按路段计算过去四个时间步平均速度”的代码。请设计一个包含两条路段、缺失值和时间乱序的小样本，用于检查分组、排序和未来信息问题。

\subsection*{练习四：改写错误预防Prompt}

选择本章中的一种常见错误，将其转化为一条可加入未来任务的 Prompt 约束，并说明还需要使用什么外部方法验证该约束是否真正被遵守。
